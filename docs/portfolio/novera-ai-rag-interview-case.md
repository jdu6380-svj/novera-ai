# Novera AI｜让企业知识问答“有据可答”

## 项目概述

Novera AI 面向企业知识管理场景，为用户提供可追溯的文档问答体验。本轮聚焦多格式资料进入 RAG 后的可靠性：不仅要生成答案，还要保留文档结构和来源位置，并在证据质量不足时采取安全处理。

## 产品判断

我的核心判断是，文档问答的关键指标不只是“能不能回答”，还包括答案是否来自正确的文件、页面、表格行或幻灯片，以及系统能否识别当前证据不适合回答。

- 按格式处理内容：Word 表格保留表头和值的对应关系，Excel 保留工作表与行定位，PPT 保留幻灯片文本和位置，PDF 与图片保留页级来源信息。
- 优先保障可验证性：低置信 OCR 内容进入复核边界，不直接作为答案依据；用户获得可解释的安全答复和下一步处理路径。
- 让评测贴近产品承诺：回答、拒答、Evidence、来源定位和文档准入分别验证，而不是仅检查答案里是否出现预期字符串。

## 迭代方案

我为固定的 20 份文档和 40 个原始问题建立独立的验收标准 v2，并逐项映射文档 profile、原始问题、证据要求和来源定位。v1 语料、Ground Truth 与历史结果保持原样；v2 将格式结构、来源证明和低置信内容的处理规则显式纳入验收。

在实现侧，补充了 XLSX/PPTX 解析、DOCX 表格结构保留、图片 OCR 置信度与解析告警；检索侧使用真实 Embedding 和进程内向量索引；回答侧通过 Evidence 校验并保留原始来源定位。对于无法可靠确认的图像内容，优先保留可信边界，而不是给出看似完整但无法验证的数值。

## 真实验证结果

最终 v2 运行对固定合成语料执行了完整处理与逐题验收：

- **文档：20/20** 通过各自 v2 profile；15 份完整解析，5 份进入受控复核/问答限制状态。
- **处理：**实际解析 40 个 chunks，其中 29 个通过问答准入并使用 DashScope `text-embedding-v2` 生成向量、写入进程内本地索引。
- **问题：40/40** 完成真实 Query Embedding 与本地向量检索，并通过各自明确映射的 v2 标准。
- **回答：**35 个问题由 DeepSeek `deepseek-flash` 真实生成并通过 Evidence 校验；5 个低置信 OCR 问题由系统安全拒答并提示复核。
- **证据：**生成回答均可追溯到检索 chunk 与来源位置；全量记录中没有无效引用或无依据声明。
- **数据边界：**向量索引在进程内运行，本轮未写入 Supabase 或 Production。

`40/40` 表示固定用例按验收标准 v2.0.0 达标，不代表面向任意企业文档的通用准确率。费用根据服务返回的 token 估算，不是账户账单。

## 能力路线

后续可在现有证据链上扩展两类能力：优先提取 Office 文件中可访问的图表源数据，再逐步验证图表视觉理解；对于手写内容，结合 OCR 置信度和人工复核建立“机器识别—确认—入库”的闭环。两条路线继续沿用来源定位与证据校验标准。

## 案例体现

这轮工作体现了从用户风险出发定义产品标准、按格式选择处理策略、在覆盖率与可信度之间作出取舍，并用真实模型调用和逐题运行证据复验产品行为的 AI 产品迭代方法。
